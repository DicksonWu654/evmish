# Site data contract

`site/data/data.json` is generated deterministically by `python3 scripts/build_site_data.py` from the 2026-10-18 baseline and 2026-10-20 gas, precompile-vector, and lifecycle matrices, plus the catalog, verification notes, and checklist. Evidence paths are repository-relative.

- `meta`: release metadata.
  - `probe_date` (string): baseline result date; `latest_probe_date` is the latest integrated run; `evidence_dates` lists both dates.
  - `chain_count` and `probe_count` (integers): counts recomputed from the baseline summary and expansion matrices.
  - `endpoints`: `{count, hosts, secondary}` for the RPC hosts used by the matrix, confirmation runs, and the independent review's round-4 G1ADD replay. Each `hosts` entry is `{host, operator}` for a chain-operated endpoint, or `{host, operator: "third-party", provider}` for a provider endpoint. Each `secondary` entry adds `{chain, host, operator, provider?, used_for, evidence?}`; the optional evidence link identifies a later independent replay outside the original endpoint registry. Hosts contain no scheme, path, query, credentials, or testnet endpoint.
  - `verification_rounds`: ordered objects with structured counts `{round, seed, sampled, correct, wrong, unverifiable}` plus the existing `date`, free-text `result`, and repository-relative `evidence` document. `wrong` counts recorded wrong/not-a-divergence/overstated verdicts; `unverifiable` is kept separate.
  - `kit_command` (string): the one-command probe-kit entry point.
- `chains`: one object per chain, sorted by id.
  - `id` (result/config identifier), `name` (display label), `chain_id` (expected integer), `endpoint` (host only or null), `block` (raw hexadecimal block number or null), `timestamp` (block timestamp integer or null), and `profile_status` (recorded result status). An unavailable chain may include a plain-English `note` explaining the recorded endpoint gap.
- `probes`: one object per probe, in the result order.
  - `id`, `name`, `category` (`opcodes`, `block context`, `precompiles`, `addresses`, `account code`, `gas/fees`, `gas schedule`, `precompile vectors`, or `lifecycle`), `sample_date`, `description` (a full sentence distinct from `name`), `init_code` (complete hex creation bytecode), and `ethereum_baseline` (interpreted Ethereum result). Expansion probes can also have a compact `label`; vector probes have `vector_source`.
  - EVM numeric values inside `ethereum_baseline` and matrix `value` objects are decimal strings. This applies to every uint256 word and values such as basefee, prevrandao, balances, and gas measurements, even when one observation happens to fit in a JavaScript number. Structural counts, chain IDs, timestamps, and other values that are bounded by the contract may remain JSON numbers. Block identifiers remain the recorded hexadecimal strings.
- `matrix`: the complete Cartesian product.
  - `chain_ids` and `probe_ids` are the axes.
  - `cells` contains one `{chain, probe, class, value, evidence, block, sample_date}` object for every axis pair. `value` is the interpreted result, or null when unavailable. `evidence` lists repository-relative raw JSON paths for the target, Ethereum control, later block, and second endpoint when recorded. `block` is that cell's captured hexadecimal block number or null.
  - Gas-schedule `value` is `{status, metric, gas, ethereum_gas, delta_gas, phase, family, confirmation_gas, second_endpoint_gas, block_tag, note}`. The metric is `gas_used` except the stipend case (`child_gasleft`). The gas numbers are decimal strings or null; `delta_gas` is target minus Ethereum and is an operation measurement, not a transaction fee/refund. A gas-bound or failed cell retains its status and is not a confirmed chain difference.
  - Precompile-vector `value` contains `status`, hex `output`, hex `expected` for valid vectors, `first_call_gas`, `second_call_gas`, `gas_scope`, and later/second-endpoint statuses. Empty success and failed inner CALL are distinct. A second-endpoint pricing disagreement is not promoted to a chain pricing finding.
    Gas is CALL-inclusive and the first call can include cold account access; neither number alone is an isolated handler tariff. Malformed-input failures that consume the 10M forwarded-gas cap use `gas_scope: "cap-exhausted-not-price"`: the gas is an exhaustion bound, not a price. Other failed valid vectors may use `bounded-failure-not-price` without proving that the cap was consumed.
  - Lifecycle `value` contains `status`, structured `outcome`, raw `observed_words`, `higher_gas_attempts`, and later/second-endpoint statuses. Simulated creation success does not prove a public transaction would be admitted; gas caps and post-transaction deletion remain unresolved where stated.
  - `class` is one of `same`, `differs`, `unsupported/execution-failure`, `rpc-rejected`, `endpoint-artifact`, `state-only`, or `unavailable`. The public names preserve the existing differential logic: `diff` becomes `differs`, execution failures become `unsupported/execution-failure`, RPC rejection becomes `rpc-rejected`, and the existing endpoint simulation/unstable/unverifiable labels become `endpoint-artifact`.
- `gas_schedule`: heatmap-ready, complete focused-probe-29 chain × item grid from the dated gas matrix.
  - `date`, `chain_ids`, and `item_ids` identify the run and axes. `items` gives each item’s `id`, `name`, `family`, `phase`, `metric`, and Ethereum baseline `ethereum_value`.
  - `cells` has exactly one `{chain, item, ethereum_value, chain_value, ratio, status, metric, evidence}` per axis pair. Values and non-null ratios are decimal strings; evidence is a repository-relative list of raw target, Ethereum, and recorded confirmation files.
  - `ratio` is `chain_value / ethereum_value` rounded to six decimal places only for a successful, comparable `gas_used` measurement (`ethereum-baseline`, `same-as-ethereum`, or later-confirmed difference). It is null for RPC failures, gas-bound results, the unfunded `call-value-empty` control, and the stipend’s `child_gasleft` metric. A non-null ratio is an operation-gas comparison, never a transaction fee or refund.
- `findings`: all catalog rows, followed by the doc-only CREATE2 note.
  - Catalog fields are `number`, `label`, `chain_scope`, `behavior`, `consequence`, `evidence_path`, `evidence_paths`, and `date`.
  - `headline` is boolean and `slug` is null or one of the six public headline slugs. Headline rows include `headline_content` with exact raw probe lines from `blog/post.md`; the BLS row also has the exact `solidity_unsafe` and `solidity_safe` snippets. The CREATE2 note has `number: null` and its note text/evidence.
- `checklist`: full-sentence strings, one for each checklist bullet in `docs/checklist.md`, preserving wrapped continuation text.
